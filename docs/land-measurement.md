# Land measurement calculator

The existing `/land-size` page now includes a mathematical parcel calculator above the retained unit converter. The Tools menu identifies it as **Land measurement & size**. New and edit Land forms link to the calculator in a separate tab so a draft is retained. Calculations run in the browser; they do not call a measurement service, require sign-in, or write listing data.

## Inputs and results

- **Rectangle:** length AB and width BC, in metres or feet. AC is calculated with `hypot(length, width)`. Optional supplied AC must agree within `max(1e-9 m, expected × 1e-10)`; rounded survey diagonals can be omitted. The generated local boundary is A(0,0), B(length,0), C(length,width), D(0,width).
- **Four sides + diagonal:** AB, BC, CD, DA and AC for a convex quadrilateral. Stable Heron products construct two triangles on opposite sides of AC. Strict triangle inequalities and convexity checks reject impossible/ambiguous configurations. Reflection and geographic orientation are not inferred. Concave land uses ordered corners.
- **All corners / Local:** 3–50 X/Y pairs in consecutive boundary order, clockwise or counterclockwise, using one Cartesian coordinate system and one unit. Supports concave polygons. The final edge closes automatically; the first corner must not be repeated.
- **All corners / GPS:** 3–50 latitude/longitude pairs in decimal degrees on WGS84. Every corner must be within 10 km of A, with latitude between −85° and 85° and longitude between −180° and 180°. Antimeridian parcels within that range work. Boundary edges use shortest geodesics.

Results include square metres, square feet, perimeter, a scaled labelled diagram, all corner coordinates and outgoing edge lengths, both diagonals for four-corner land, and a local area centroid where applicable. Both complete Nepali systems are shown: Ropani–Aana–Paisa–Daam and Bigha–Kattha–Dhur. Fractions remain in the final unit and display rounding carries into the next unit. Both tools use shared `NEPALI_AREA_IN_SQM` factors derived from the square-foot relationships in the [DUDBC Construction Handbook conversion table](https://www.giwmscdnone.gov.np/media/app/public/54/posts/1711001516_6.pdf): 1 ropani = 5,476 ft² and 1 bigha = 72,900 ft². Metric factors use exactly 0.09290304 m²/ft² rather than rounded metric entries. Existing listing values and historical database/formatting conventions are not migrated by this tool extension.

The converter accepts ropani, aana, paisa, daam, bigha, kattha, dhur, square feet or square metres individually, and combined Ropani–Aana–Paisa–Daam or Bigha–Kattha–Dhur inputs. Enter 0 for unused compound units. Larger compound units must be nonnegative safe whole numbers; daam/dhur may be fractional. Extra lower units normalize automatically: 16 aana becomes 1 ropani and 400 dhur becomes 1 bigha. English and Nepali digits are accepted in all area, dimension, side, diagonal and local/GPS coordinate fields, including scientific notation and the Unicode minus sign. Invalid or partial converter inputs clear the outputs and show recovery text. Changing input system converts the current valid area into the selected notation. Downloads include `nepaliArea.convention` with `ropaniSqFt`/`bighaSqFt`, plus named `ropaniAanaPaisaDaam` and `bighaKatthaDhur` objects alongside the unrounded geometric result.

GPS results retain the entered geographic boundary, link corner A to a map and export raw measurement JSON with ordered `{lat, lon}` coordinate objects, WGS84 reference, decimal-degree coordinate units and an explicit shortest-geodesic edge model. This format preserves clockwise/counterclockwise and date-line inputs without implying Cartesian GIS line semantics. The map link opens the supplied corner, not an inferred address or parcel centroid. Local results export ordered `{x, y}` coordinate objects in metres, a local Cartesian reference and straight-segment edge model. Both reports identify consecutive boundary order with automatic closure, metre length units, square-metre area units and schema version 1; they include raw area, perimeter, sides and diagonals. Only the local report includes an area centroid. The GPS report excludes projected preview geometry and its projected centroid. Downloads are named `land-measurements.json` and retain raw IEEE-754 numeric values; display rounding is not fed into subsequent calculations.

## Numerical method and supported precision

Feet are converted using the exact international-foot factor `0.3048 m`. Local polygons use translated, normalized shoelace terms, compensated summation and the signed-area centroid formula. Translation avoids cancellation with large survey-grid offsets. Coordinates must be finite and within ±1 billion input units. Lengths/span must be between `1e-6` and `1e7 m`; normalized geometric predicates use `1e-12` tolerance. Duplicate, crossing, touching, overlapping, zero-area and numerically unresolved boundaries are rejected. Inputs accept complete English/Nepali decimal or scientific notation; blanks, partial numbers, grouping separators, hex and nonfinite values are rejected. Nepali digits normalize before strict validation. Changes to input values, method, units or coordinate system immediately clear previous results, and failed calculations focus an actionable error.

GPS area and distances use the pinned MIT-licensed `geographiclib-geodesic@2.2.0` WGS84 ellipsoid implementation. The azimuthal-equidistant local representation is used for preview and topology validation, not for reported GPS area or distances. It is a parcel-scale tool with the extent/range restrictions above, rather than a general global GIS topology engine. Nearly coincident or ill-conditioned boundaries should be measured again; measurement uncertainty cannot be removed mathematically.

The shared Nepali converter/decomposer supports finite nonnegative areas through `1e15 m²`, including zero. This cap covers the geometry tool's supported span and rejects extreme finite inputs before numeric conversion/decomposition can produce overflowing results. Compound conversion normalizes lower-unit overflow and retains a fractional final unit. Display decomposition rounds the final unit to six decimals before carrying; genuinely tiny nonzero parts use significant figures so they remain visible. Download decomposition does not apply display rounding. These tool-specific square-foot-derived factors intentionally coexist with unchanged legacy listing/database formatting factors; this feature performs no data migration.

Length and area are horizontal plan measurements. Sloping distances must first be reduced to horizontal distances. Dimensions determine size and a local shape; geographic location requires supplied geographic coordinates. Coordinate/survey accuracy determines real-world accuracy. The feature does not establish surveyed ownership boundaries or recover a geographic address from lengths.

Reference: [GeographicLib JavaScript documentation](https://geographiclib.sourceforge.io/html/js/) and [WGS84 polygon API](https://geographiclib.sourceforge.io/html/js/module-geodesic_PolygonArea.PolygonArea.html).

## Incumbent interface

The calculator reuses the existing Poppins, royal blue, crimson and white interface and shared Field, Input, Select and Button controls. The boundary is a mathematical SVG diagram. Desktop places the form beside the preview/results; phones stack them in reading order, with a labelled, focusable horizontal region for the coordinate table. The calculate action locally overrides its hover to crimson-700, giving white 14px text 6.71:1 contrast; the shared button variant, global `DESIGN.md` and token sidecar are preserved. There is no new shipping raster artwork.
